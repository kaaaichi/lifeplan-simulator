## Context

`src/engine/simulate.ts`の年次ループ（24〜87行付近）は以下の順で現金・投資残高を計算している。

```ts
const annualCashFlow = income - totalExpense + financialEventsTotal
const contribution = a.annualInvestmentContribution + oneTime
const investmentReturn = invest * r
invest = invest + contribution + investmentReturn
cash = cash + annualCashFlow - contribution
```

投資への拠出額`contribution`は単年度収支と無関係の固定額であり、現金残高にはガード（下限）が一切ない。ユーザーの実データでは2027年に現金残高-88万円、2028年に-27万円という状態が既に発生しており、資産全体（現金+投資）は増え続けているにもかかわらず「現金が尽きている」という非現実的な表示になっている。

## Goals / Non-Goals

**Goals:**
- 年末の現金残高が生活防衛資金の閾値を下回る年について、投資資産を取り崩して現金を補填し、より現実的な資金繰りをシミュレーションに反映する
- 閾値を`Assumptions`のフィールドとして持たせ、入力フォームから世帯ごとに調整できるようにする

**Non-Goals:**
- 現金残高が閾値を上回っている（＝余剰がある）年に、その余剰を自動で投資へ回すロジックの追加（現状の固定拠出額ロジックはそのまま維持する。ユーザーからの要望は取り崩し方向のみ）
- 投資残高でも取り崩しきれない場合の借入・信用取引等のモデル化（単に投資残高を0にして終わる）
- シナリオ（楽観/中央/悲観）ごとに異なる閾値を設定する機能（閾値は共通の`Assumptions`フィールド1つのみ）

## Decisions

1. **取り崩しのタイミング**: その年の`cash`/`invest`を現行ロジック（拠出・利回り込み）で計算し終えた後、年末時点で1回だけ判定・実行する。売却した投資資産がその年の利回りを得られたかどうかは区別しない（年次粒度のモデルにおける簡略化）。
2. **閾値の保持場所**: `Assumptions.emergencyFundCash`という新規フィールドとし、`investmentReturnRate`等の既存パターンに倣う。デフォルト1,200,000円。ハードコード定数にはしない（入力フォームからの調整を可能にするため）。
3. **投資残高不足時の挙動**: `drawdown = Math.min(shortfall, Math.max(invest, 0))`とし、投資残高を0円まで取り崩す。それでも不足する場合は現金は閾値未満（マイナス許容）のまま残す。既存エンジンにも他に明示的なガードはない（`coastFire`計算の`Math.max(0, ...)`が唯一の先例）ため、この方針は既存の設計思想と整合する。
4. **3シナリオへの一律適用**: `selectors.ts`が`simulate()`を返り値の異なる利回りで3回呼ぶ際、いずれの呼び出しにも同じ`emergencyFundCash`とロジックを適用する。シナリオ間で閾値を変える要件はない。
5. **既存データの移行**: 本番Firestoreの既存`HouseholdDoc`には`emergencyFundCash`が存在しないため、`src/persistence/migrate.ts`で読み込み時にデフォルト値1,200,000円を補完する（schemaVersionを1つ上げる）。

## Risks / Trade-offs

- **ゴールデンマスター回帰**: 2027年は現行シミュレーションで現金残高が-88万円（閾値120万円を下回る）であることが実データで確認済みのため、この変更により2027年の投資残高が変化する可能性が高い。総資産（cash+invest）自体は変わらないため大きなリスクではないが、`tests/golden.integration.test.ts`の許容誤差（±5%）を超える場合は、スプレッドシート（一次資料）が本ロジックを持たないことによる意図した乖離として扱い、必要ならフィクスチャを更新する
- **非対称性**: 取り崩し（赤字→投資取り崩し）のみを実装し、黒字時の自動投資は行わないため、余剰が出る年は引き続き現金残高が閾値を大きく上回って積み上がる（現行と同じ挙動）。ユーザーの要望範囲外だが、UI上は「現金だけ妙に多い年がある」という見え方が残る点は申し送り事項とする
- **永続化・マイグレーション**: 本番データへのスキーマ変更を伴うため、マイグレーション適用後に既存シナリオが問題なく読み込めることをエミュレータ等で確認する必要がある
